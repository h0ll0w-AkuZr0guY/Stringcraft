# 质量与验证

当前为预览版。工程可运行与音乐可用性分别验收，不以成功生成文件替代听感、识别正确率和真人试弹。

0.2 后续验收按用户选择采用真实曲谱对照与约束校准为主，详见 [真实曲谱评估](REFERENCE_EVALUATION.md)。实际试弹可补充，不作为当前交付阻塞项；下方首版门槛和历史记录保留，不能将其理解为已完成证明。

## 0.2 开发验证

新增原创双声部 MusicXML 短谱，覆盖延音/连奏/休止/变速/变拍往返；新增和弦指型、四指、横按、持续占用、声音激励和间距回归。独立标准读取器接受导出的 MusicXML。具体发布缺口见 [音乐开发验收](MUSICAL_DEVELOPMENT.md)。以下 0.1 合成模型与实曲流程记录不作为新版实曲准确率。

## 固定样本

scripts/generate-fixtures.py 生成 12 段原创合成音频与精确音高/起音标注：升降音阶、重复、延音、低/高音、跳进、柔和起音、低音/持续垫底混合及静音。它们不是专业真实录音，也不是流行歌曲基准。tests/fixtures/audio/truth.json 是真值，生成规则可复现。

音乐单元测试覆盖四档指法约束、延音与同音重弹、capo/transpose、锁定保留、音域、省略、连续旋律、项目校验和基础导出。Playwright 使用真实音频上传，启动真实 WASM 模型，并测试校谱、插件与保存流程。

模型评估按同音高且起音误差不超过 50 ms 一对一匹配，报告 precision/recall/F1；另报 100 ms 作为诊断，不替代正式门槛。静音误报独立报告。新旧版本使用同一输入、相同阈值和模型环境，不能混用旧截图或历史统计。

## 正式质量门槛

1. 干净单旋律样本匹配 F1 达到 0.90。
2. 真实混音主旋律 F1 中位数较冻结旧版至少提升 0.10；单项下降超过 0.05 需处理或缩小能力声明。
3. 三段初学、三段进阶编配经吉他演奏者试弹，记录节奏、换把、跨度与听感反馈。
4. 锁定编辑、音符时间与导出往返无实质回归；全部硬指法约束通过。

上述真实混音比较与真人试弹尚不能由代码自测证明。未完成时只发布 preview，不标成稳定版，不宣传整曲高准确率。当前算法不可靠地推断拍号、和弦功能或原曲技法；网页 BPM 暂由用户校正。

## 可重复运行

生成样本后运行 npm run test:e2e；模型评估通过 scripts/evaluate-browser.mjs 执行，保存 JSON 和 Markdown 到 artifacts/quality。只把经过审阅的汇总写入此文档，私人音频和原始识别结果留在忽略目录。脚本区分浏览器模型指标与编配规则指标，不做自动“已达宣传效果”的结论。

## local.2 伴奏和声实验

新增 88 项单元回归、10 项后端检查、26 项普通浏览器流程通过；6 项需显式语料或 Key 的测试跳过。秒时间轴回归确认 68.5 与 135.7 BPM 产生同一和弦时间范围，原始音符不变。授权录音前 30 秒的真实本地界面运行取得 309 个原始音符、18 段和声区间；两种 BPM 均能生成非空伴奏，分离伴奏/低音可播放，WAV 非静音，三种和声方案可切换，重复输入复用缓存，任务可取消。事件数量随伴奏节奏改变不代表识别内容改变。

长曲 WAV 增加 1200 次真实采样发声回归，验证共享一个解码缓冲而非按每次发声重解码。修复前，整曲高事件数导出在 30 秒测试窗口内未返回；该失败保留为性能问题，不将延长测试超时本身当成修复。WAV 渲染仍随曲长和机器性能耗时，界面保留渲染状态。

本机 RTX 4060 Ti 实际执行 HTDemucs 与 BTC CUDA 推理，Basic Pitch 使用 ONNX CPU；另实际跑通 CPU 分离路径。设备和权重摘要保存在项目分析记录。流程通过不代表听感或可演奏性已经通过真人验收。

冻结 BTC 只识别大小三和弦及 N。六段真实 GuitarSet 评估包含明显漏识别和分离后退化，未通过逐曲质量门槛，详见 [参考评估](REFERENCE_EVALUATION.md)。因此增强为主动选择的实验模式；没有上线训练，也没有将合成样本成绩解释为商业混音识别准确率。

## local.3 音乐编配诊断

同一批私人《晴天》来源输入分别比较旧编配与新编配。开头 17 个和弦区间实际为 4 种和弦，整曲为 6 种，修正界面混淆。120 BPM 未确认开发网格下，整曲和声从 121 段合并为 119 段，种类保持 6 种；68.5 和 135.7 两种参考网格均可生成整曲指弹并保留各自选定的旋律骨干。选定骨干由算法决定，不能把保留率当录音旋律准确率。未知和声、缺少指型等警告继续保留。

授权整曲 269.7467 秒实际运行约 107.71 秒，3352 个原始 BP 音符、113 个人声证据片段；HTDemucs/BTC 使用 CUDA，BP/pYIN 使用 CPU。人声证据稀疏，尚不能解决整曲主旋律可靠识别。原始音符、来源和声和人工材料不被派生编配覆盖。

三段 30 秒试听按同输入、68.5 参考网格提供四组合：旧动作/旧音源、新动作/旧音源、旧动作/新音源、新动作/新音源。每组使用同一 LUFS 目标和线性增益，保留原始 WAV、响度记录与项目；36 个文件均无合成音高回退。没有由自动统计宣称主观听感提升。

冻结的三组已知谱验收通过：前奏单线片段音高/起音保真，主歌与副歌的独立声部、时长、弦位、技法/闷音保持原门槛。参考是 Steven Law 改编谱，独立节奏复核与原录音对齐仍未完成；不当原录音逐音真值。首 8 小节混合输入按既有前奏/伴奏切片评估，不能用整段候选 dropped 数推断旋律丢失。

六段 GuitarSet 冻结开发录音用同一秒区间及人工核验和弦标注检查派生和声。初候选在 Jazz 段下降 11.26 个百分点，已拒绝：长结构和弦不得仅因非和弦旋律改写，未确认网格不移动边界。修订后五段指标不变，Funk 段下降约 0.37 个百分点。原有 Bossa 漏识别和 Jazz 类型限制未解决，不宣传跨曲目准确率提升。汇总含失败候选与所有分母，见 [和声回归](../benchmarks/music-harmony-local3.json) 和 [动作诊断](../benchmarks/music-arrangement-local3.json)。全部已用于观察，不是新留出集。

工程检查包括 104 项单元测试、28 项普通浏览器流程（6 项显式语料/付费/录制流程跳过）、10 项后端测试及完整环境的 3 项人声证据检查。浏览器新增分声部试听、来源/派生隔离、失效提醒及跨渲染块延音回归。测试通过、采样数量和模型实际运行均不等于演奏者听感验收。

## local.4 多轨与播放验收

114 项单测、17 项后端测试、31 项普通浏览器流程通过，另 7 项依赖显式语料/录制/服务的流程默认跳过。变更后的录音关联、长曲定位、轨道校订和谱面交互另重跑 12 项通过。覆盖：暂停续播、播放中 seek、循环外定位、异步准备取消、手动浏览恢复、拖动与试听分离、轨道历史、工程归档摘要与路径校验。

授权《晴天》269.7467 秒实际先分离、再转录：伴奏 3228 个 BP 候选，人声另行分析 905 个 BP 候选及 123 段 pYIN 证据。HTDemucs/BTC 使用 CUDA，BP/pYIN 使用 CPU。界面完成整曲指弹、252808184 字节含音频工程导出、重新导入与作品库重开。候选数和非空谱面不表示识别准确；人声证据仍稀疏，连音音源仍为近似。

三组冻结参考谱继续通过原有门槛。原有 17 组音乐动作诊断与六段 GuitarSet 开发录音重新运行，后者派生和声结果与 local.3 完全一致；前者部分音频输入因经过音与句尾保护增加骨干，但已知谱旋律保留不变。这些材料已用于开发观察，不称为新留出集。详见 [本轮诊断](../benchmarks/music-arrangement-local4.json)。

Windows 打包验证使用 scripts/verify-local-trial.mjs（屏蔽外网，真实 WASM、续播与导出），完整环境再用 scripts/verify-native-trial.mjs（真实分离、独立试听、BPM 不改写材料与缓存）。实际产物报告随本机交付；不因源码测试通过而假定 EXE 已通过。

实际 Windows 基础 ZIP 已独立解压并以仅含系统目录的 PATH 启动，程序构建 96c29b3d91a4。屏蔽外网后完成真实 WASM 识别、直接单线编配、续播、跳转、WAV/MIDI 导出和重开，导出 WAV RMS 约 0.01344；另一独立资产目录导入整曲音频工程，原曲、人声及伴奏可播放。完整环境另实际执行 CUDA 分离，合成 4.5 秒样本得到 15 个伴奏候选和六条音频轨，68.5/135.7 BPM 分别生成 10/20 个事件，原始候选与和声不变，重复输入命中缓存；两套检查的外网请求与浏览器错误均为空。ZIP 与独立解压的 1154 个成员通过摘要/CRC/尺寸核验。同版本端口复用返回成功。以上仍为工程流程验收，不代表复杂歌曲听感或识别正确率达标。

## local.5 乐句实验晋级检查

同一输入、同一速度与指型设置比较稳定和实验配置。独立合成人声帧验证短八度误差、重弹证据与真正休止。另核对 3/4 的刷弦方向和力度，以及持续低音对短和声的影响。

三组《晴天》冻结参考谱均通过已有的记谱保真门槛。六段 GuitarSet 开发录音中，五段的时长加权和弦主次调一致率持平，Jazz2 从 77.29% 到 78.33%。其中一段仍只有 29.05%，这六段此前已用于开发。

在本机授权整曲上，两套使用相同的 905 个 Basic Pitch 人声候选。pYIN 派生证据从 123 段变为 234 段，最终指弹规划的旋律骨干从 519 个降至 495 个。真实歌曲的逐音正确率和真人听感仍缺少达标证据。扫弦发声事件从 2710 到 2636，分解和弦保持 1105；事件数量不作为听感指标。稳定配置沿用，实验通过专业模式手动选用。[固定材料与统计](../benchmarks/music-arrangement-local5.json)

在完整环境运行 tests/native_melody_check.py 可重跑独立帧检查。设置 STRINGCRAFT_COMPARE_PROFILES=1 后，scripts/evaluate-musical-arrangement.mjs 接受已有私人清单并输出两套配置的诊断；指定 harmonyOnly 的项输出分段供现有 evaluate-harmony.py 的同一标注方法计分。参考谱、音频和对照 WAV 留在测试机上。
## 0.2.0 的指弹与单线练习

用相同的《晴天》本地整曲转录对照经典与实验乐句方案。整曲独奏指弹中，伴奏低音与旋律的重叠指标从 0.95 降到 0.91，同时保留的旋律事件从 519 降到 495。三个有书写谱面作为输入的八小节片段保留的旋律事件数一致，冻结回归三组通过。合成谱与参考片段的回归仅检验编配与谱面，完整录音仍需要旋律识别与试弹评估。实验方案作为专业模式选项，经典方案继续用于常规生成。

单线练习的实验方案每组起音只选一个音，并增加快速换把与跨弦的代价；留白使用原有事件间隔。钢琴夹具覆盖双谱表转写、跨小节连音和 MIDI 导出。
