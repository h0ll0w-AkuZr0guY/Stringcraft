# local.4 本地试用

本轮先在本机试用，不上传 GitHub、Pages 或公开 Release。主界面为统一多轨工作台，详细操作见 [使用指南](USAGE.md) 和 [音乐知识与约束](MUSIC_KNOWLEDGE.md)。

基础包只需完整解压后运行 Stringcraft.exe。模型环境独立安装；本机升级包可通过启动脚本中的 STRINGCRAFT_PLUGIN_DIR 复用已验证环境，避免重复解压数 GB。脚本路径仅用于本次本机交付，不进入公开源码。

默认先分离，再转录伴奏；人声轨可先试听、按需分析。音乐网络仍为实验候选，复杂指弹与连音音色需要继续校订。含音频工程 ZIP 能迁移分轨，JSON 只保存谱面和引用。assets 独立于任务缓存，当前不自动回收未引用音频；大工程需留意磁盘容量。

## 使用与排错

1. 解压后启动基础程序；已有模型环境用本次交付的“启动本地试用”脚本复用。顶部应显示 local.4，设置中应显示实际 GPU/CPU；缺环境时只能快速基础识别。
2. 上传音频，等待进度完成；人声与伴奏各自成轨。原曲、伴奏、人声可独立试听。指弹首次生成会增加人声旋律分析阶段。
3. 主播放条暂停后续播；点击谱面跳转；手动浏览后点“回到播放位置”。编配设置和属性可以收起。
4. 含音频工程用 ZIP 导入/导出；JSON 不携带声音。旧 JSON 可继续打开，原始音符和人工修改保留。
5. 基础程序内置 WASM 模型和吉他采样，无需 Key；可选 AI 默认关闭，不参与本轮验证。

若端口被旧版本占用，请关闭旧服务窗口后再启动。相同版本可复用服务，旧版本不会被静默打开。首次本地分离会较慢；可以取消，已有作品保留。分离缓存与永久 assets 分开，不用删除任务来清理工程音频。

关闭控制台会结束本地服务；音频和作业默认在系统用户目录 Stringcraft，启动脚本可通过 STRINGCRAFT_DATA 指定独立目录。浏览器项目保存按地址隔离；换端口后用工程包导入，避免误认为作品丢失。

准确率和听感仍需按带真值的材料评估；网络候选、自动和声整理与生成的指法不冒充原谱。未经本地试用验收不发布线上版本。
