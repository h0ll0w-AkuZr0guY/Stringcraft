# 架构

## 一个工作台，两种计算环境

GitHub Pages 和本地基础包使用同一份 Vite 构建。网页承担项目编辑、乐器编配、播放和导出；可选本地服务执行独立模型进程。Pages 没有服务端音乐计算，浏览器不需要把音频发送给维护者。

`音源 → 原始候选 NoteEvent → 节拍/和弦证据 + 旋律候选 → MusicalScore → ArrangementDraft → 乐器动作计划 → 谱面 / 音频 / 导出`

独立 `rhythm-analysis` 插件从解码波形计算起音与周期候选，经 Worker 返回 `TimingAnalysis`，与音符间隔估计并列供试听。候选始终未确认，不自动覆盖速度或小节首拍；选用速度只调整音乐网格，原始音符秒时间不改。解码数组可复用，音符模型仅转移其副本到 Worker。

0.2 开发分支引入 SDK v2。`packages/contracts/score.ts` 只描述音乐结构：拍、速度图、拍号图、声部、休止、延音与连奏关系、和弦及来源。`InstrumentPluginV2<Options, Action, Notation>` 的参数和动作由乐器包定义。吉他包独立拥有指型、弦位、左右手指法、扫弦、击勾弦与占用验证；钢琴契约验证包使用琴键、双手、指法和跨度，不依赖吉他调弦。

SDK v1 入口保留为迁移适配器，工作台的编辑和保存投影当前仍针对吉他。v2 通用能力不代表钢琴工作台已经实现。新项目含 v2 音乐结构；旧项目只在用户点击“升级为 v2 副本”后取得新身份，原项目不覆盖。详细进度和未完成项见 [音乐开发验收](MUSICAL_DEVELOPMENT.md)。

原始材料保留在浏览器 IndexedDB；MusicProject 导出只含音符与配置，不自动包含原音频。模型失败保留原项目，不生成虚假成功。当前网页采用轻量 React 状态和有界历史，持久化通过独立存储层。

录音身份与音乐编辑独立：浏览器分析保存输入摘要，`audioReference` 指向当前对照文件与偏移。文件按项目 ID 和摘要缓存，重新关联保留原始识别时间及锁定谱面；撤销可回到旧文件，删除项目统一清理。旧项目仍支持原缓存键，显式升级副本时复制关联文件。

## 依赖方向

`contracts ← music / storage / plugin-host ← plugins / app`

contracts 无具体乐器依赖，NoteEvent 仅描述音乐事实。Arrangement 与 MusicProject 的音符类型可通过泛型扩展；默认吉他事件包含弦、品位。通用音符编辑器直接处理 NoteEvent，不附加吉他约束；吉他编配的保存校验仍针对吉他。键盘复音试听已独立，钢琴双手/踏板编配仍需独立适配与验证。

旋律与编配插件导出 SDK 函数。安装器校验 catalog 中 SDK、运行环境、文件长度和 SHA-256，代码与上一个版本写入 IndexedDB，执行前检查启用状态。应用通过组合入口调用插件，不让宿主导入具体算法。插件是可信代码扩展，Worker 用于性能隔离，不能声称构成恶意代码沙箱。

## 时间模型

NoteEvent.start / duration 与 sourceOffset 都是秒。sourceOffset 表示选定片段在原文件中的偏移；编配事件时间相对片段。BPM 只影响节奏显示、MIDI 时间换算与后续重新编配；播放原事件不拉伸。慢速播放只改变播放调度，不修改项目。节奏谱近似到十六分网格，图形六线谱按音乐小节与最小列间距排版，播放与编辑仍保存秒时间。

## 算法与乐器

Basic Pitch 在 WASM Worker 预测候选；旋律追踪对近同时起音分组并保留连续声部；吉他编配使用有界候选搜索与持续占用验证。主旋律优先，v2 伴奏来自和弦指型和节奏型，指弹只加入结构低音；不会把所有剩余候选当和声。低置信度、超音域或违反动作约束的音符省略并记录原因。

人工改谱自动锁定。重新编配先验证锁定集合，再以锁定集合为不可变约束；无法满足时返回错误。当前不把删除当作永久屏蔽，重新编配可能重新引入已删除的自动音符；需要永久保留编辑时导出项目或锁定替代音符。

## 本地任务

FastAPI 仅监听 127.0.0.1，拒绝非本机 Host 和跨来源请求。写操作和作业查询需要每次启动生成的会话 token；无跨域代理。每次最多一个重任务，上传 200 MB，任务使用随机目录，输入在结束后删除，结果保留，超过 24 小时的旧任务目录在启动时清理。

后台启动指定插件 Python 子进程。取消会终止进程树，模型拥有独立依赖；服务退出也回收进程。进度采用 JSON lines，模型日志不进入网页。已完成的增强作业按源摘要、范围和管线版本复用，24 小时内可从持久化结果恢复；取消或失败作业不复用。用户作品依靠浏览器或导出项目保留；local.4 的分轨音频另存 assets，不随作业过期。

`plugins/audio-harmony` 拥有 FFmpeg 解码、Basic Pitch ONNX、HTDemucs、冻结 BTC 大小三和弦网络及音频模板消融，不引入通用宿主依赖。启动后台探测校验权重摘要，并实际执行 CUDA 张量计算；任务记录实际设备和显式 CPU 降级。框架不提供隐式联网下载或自动训练。模型质量仍标为实验；按用户要求，本地工作流默认先分离，质量门槛未过不能宣称网络已晋级或准确率已达标。

`HarmonyAnalysis` 保存独立的秒区间，和弦网格通过 `projectHarmony` 投影；候选参与预览并标记，N 保留休止，人工/导入和弦优先。基础音符和声同样采用固定秒窗。原始 notes、模型和声、编配节奏分别保存，改 BPM 只改变投影与弹奏型。

## 整曲编辑数据流

上传 → decodeWhole（50 MB / 300 秒）→ basic-pitch-stream Worker → 每 6 秒原始候选快照 → 主机编辑覆盖层 → piano-roll 视口绘制 / note-audio 试听 / note-exporters MIDI。宿主保存状态、取消令牌、独立撤销历史和持久化，插件不接触 React 状态或存储。WASM 推理按块释放临时张量；相邻块有 0.5 秒上下文，并区分持续边界与真实重弹。

MusicProject.notes 是不可由校订写入的原始候选，noteEditor 是 ID 覆盖/删除记录。后续原始快照不会覆盖人工修改；撤销删除会重新显示最新的原始候选。历史最多 100 个命令，超出部分折叠进 base。筛选是投影，不删除原始材料。停止、超时或错误保留部分进度；新任务拥有独立令牌，旧任务的回调与 finally 不得修改新任务。

吉他入口显式采用当前校订/筛选结果重新提取旋律，之后按原有音乐结构与乐器动作编配。通用音符导出不经过吉他，避免丢失和弦与复音。详见 [音符编辑器](NOTE_EDITOR.md)。

## 本地试用的生成任务

吉他生成由 packages/music/generate 协调：输入/插件检查 → 旋律 → 和声 Worker → 指型候选 Worker → 可选建议 → 编配 Worker → 校验提交。生成状态是应用会话状态，独立于识别进度，不写入 MusicProject。任务有稳定 ID、阶段、开始/结束时间、错误及恢复动作；重复点击受同步锁保护，总时限 120 秒，取消不进入 AI 回退。

结果必须非空、通过 validateProject，且生成期间项目未被替换或修改，才进行一次提交并宣布成功。提交失败抛回任务层，不允许内部吞错后继续宣布完成。原始材料、锁定编辑和上次成功谱面在失败/取消时保留。统一工作台只保留一个任务反馈入口，音乐结构校正默认折叠在谱面之后。

## 音乐规划与吉他动作

`plugins/arrangement-planner` 是内部算法插件，在可取消 Worker 运行，不导入吉他规则。它复制来源结构，按局部调性、持续时间、旋律非和弦音权重、前后和声和全局时长先验整理弱候选。人工/导入和弦、旋律与完整延音链受保护，罕见属和弦解决关系单独保留。短空窗只在相同和弦、持续旋律且无明确休止时补全，并标为 generated。原始识别层不改写。

可选 `MusicProject.arrangementDraft` 保存规划来源修订标识、选项、派生 score、建议乐句、决策和统计。`project.score` 保留来源校正；`arrangement.score` 使用派生结果，谱面、试听和导出仍来自同一演奏动作。修订标识仅供失效检查，不充当安全摘要。旧项目没有 draft 字段也有效。

吉他 `melodic-position` 在乐句内搜索弦位与整句八度，检查持音和移动，为低音预留空间。人工/导入旋律不自动移八度；规划后的旋律骨干若不能保留则报错。低音和稀疏内声部在持音全区间验证后加入。`strumming` 按拍组、重音、弦组、刷弦时间曲线和句尾留白生成动作，固定分解模式保留原节奏。当前仍是有界启发式搜索，不是人体或审美的完整模型。

本地 `audio-harmony/melody.py` 在有界窗口提取高置信 pYIN 人声证据，边界不产生假重弹；它与 BP 原始复音独立保存。音源按实际弦、音高、奏法和力度层选择实录，WAV 分块保留采样衰减位置并共享解码缓存。原始实录单次录制，无专门连奏采样，听感近似如实标明。

## local.4 多轨与统一时钟

工作台采用轨道列表、谱面视图和可收起属性/设置，共用 `Transport`。位置以音频时钟为准；暂停保留位置，回到开头才归零，播放中 seek 重建同一驱动。所有 stem 与音符合成在同一个 AudioContext、同一 origin 调度。`packages/music/track-playback` 管声音调度，React 只表达意图。`useTransport` 让活动视图订阅，隐藏视图保留视口但不订阅时钟。`useScoreFollow` 支持手动浏览暂停跟随与显式恢复。

本地默认先 HTDemucs 分离，再 Basic Pitch 转录伴奏，BTC 分析器乐和声。人声独立成轨，首次指弹或用户显式请求时，从已存 stem 分析；不重复分离。扫弦、分解与单线练习采用器乐，指弹采用人声旋律和器乐和声。快速浏览器识别仍可显式选择，但不标为分离。默认工作流选择本地分离不表示模型质量已通过晋级，网络仍为实验状态。

`backend/assets.py` 的内容寻址 PCM 文件独立于 24 小时 jobs 缓存；工程引用按项目记录，删除任务不删除资产。删除项目只释放引用，当前不自动回收未引用资产，磁盘占用会累积。含音频工程 ZIP 携带项目、清单和音频摘要，导入验证全部文件后才注册。只导出 JSON 不能迁移音频。

轨道只读原始候选和独立覆盖历史保存在 `ProjectTrack`，旧顶层原始 notes 和编辑 ID 不改写。派生吉他轨道仍使用乐器动作编辑；所有后续乐器复用秒时间和 ScoreHit/ScoreRegion 契约，提供自己的谱面几何。音乐规则在插件，详见 [音乐知识](MUSIC_KNOWLEDGE.md)。

## Windows 宿主与工作台布局

WinForms 主窗口与通知区域图标负责应用生命周期，WebView2 运行同一前端。按 Windows 用户限制单实例。宿主生成每次启动独有的私有请求令牌，管理仅绑定环回的服务子进程；普通浏览器无法访问桌面专用端口。工作台使用 WebView2 独立用户资料。托盘隐藏只暂停听音，退出由前端落盘确认后结束服务和进程树。网页构建保留普通浏览器入口。

React 使用同一页面框架的侧栏、标题栏与内容间距。统一工作台的常规区包含生成与谱面，专业区保留播放条并显示配置页。音符卷帘、吉他六线谱和节奏谱从 Transport 的秒时钟各自推导当前区域。显式 seek 重启跟随，滚动悬停和拖动视图控制只改变视口。六线谱按实测内容宽度和缩放重新排版，多余密度留在独立滚动区。节奏谱使用 alphaTab 渲染后的真实节拍边界。

音频机器输出与人工校订继续保存在各轨。人声作业一次解码出稳定版证据和可选乐句证据；旧项目没有二者中新增的一条时仍然有效。实验选择另记于生成结果与派生谱，不引入新的项目版本。

## 0.2.0 乐器谱与练习

项目可追加独立的钢琴演奏计划和作品卡片样式，旧 JSON 继续以原结构打开。钢琴适配器读取谱表、分配双手并输出大谱表；吉他的弦品信息仍留在吉他插件。谱面与跟练共享秒时钟，练习离开时恢复工作台的原位置、速度和循环。

公开试玩和完整版评分实现独立。应用只通过练习契约传递谱例和输入。完整版 ZIP 只接受三个指定文件，先校验发行签名和摘要，再执行模块，最后替换旧数据。信任根仅含发布公钥，签名私钥和完整版源码在公开仓库之外。
