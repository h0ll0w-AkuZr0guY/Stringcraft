# 架构

## 一个工作台，两种计算环境

GitHub Pages 和本地基础包使用同一份 Vite 构建。网页承担项目编辑、乐器编配、播放和导出；可选本地服务执行独立模型进程。Pages 没有服务端音乐计算，浏览器不需要把音频发送给维护者。

`音源 → 候选 NoteEvent → 旋律追踪 → 吉他编配 → 可编辑 Arrangement → 谱面 / 音频 / 导出`

原始材料保留在浏览器 IndexedDB；MusicProject 导出只含音符与配置，不自动包含原音频。模型失败保留原项目，不生成虚假成功。当前网页采用轻量 React 状态和有界历史，持久化通过独立存储层。

## 依赖方向

`contracts ← music / storage / plugin-host ← plugins / app`

contracts 无具体乐器依赖，NoteEvent 仅描述音乐事实。Arrangement 与 MusicProject 的音符类型可通过泛型扩展；默认吉他事件包含弦、品位。当前应用的编辑器和持久化校验按吉他实现，接入键盘等需要新增相应编辑适配与校验器，不能只改显示名称。

旋律与编配插件导出 SDK 函数。安装器校验 catalog 中 SDK、运行环境、文件长度和 SHA-256，代码与上一个版本写入 IndexedDB，执行前检查启用状态。应用通过组合入口调用插件，不让宿主导入具体算法。插件是可信代码扩展，Worker 用于性能隔离，不能声称构成恶意代码沙箱。

## 时间模型

NoteEvent.start / duration 与 sourceOffset 都是秒。sourceOffset 表示选定片段在原文件中的偏移；编配事件时间相对片段。BPM 只影响节奏显示、MIDI 时间换算与后续重新编配；播放原事件不拉伸。慢速播放只改变播放调度，不修改项目。节奏谱近似到十六分网格，图形六线谱采用真实秒时间轴。

## 算法与乐器

Basic Pitch 在 WASM Worker 预测候选；旋律追踪对近同时起音分组并保留连续声部；吉他编配使用有界候选搜索与持续占用验证。主旋律优先，附加声部来自候选输入。低置信度、超音域或违反动作约束的音符省略并记录原因。

人工改谱自动锁定。重新编配先验证锁定集合，再以锁定集合为不可变约束；无法满足时返回错误。当前不把删除当作永久屏蔽，重新编配可能重新引入已删除的自动音符；需要永久保留编辑时导出项目或锁定替代音符。

## 本地任务

FastAPI 仅监听 127.0.0.1，拒绝非本机 Host 和跨来源请求。写操作和作业查询需要每次启动生成的会话 token；无跨域代理。每次最多一个重任务，上传 200 MB，任务使用随机目录，输入在结束后删除，结果保留，超过 24 小时的旧任务目录在启动时清理。

后台启动指定插件 Python 子进程。取消会终止进程树，模型拥有独立依赖；服务退出也回收进程。进度采用 JSON lines，模型日志不进入网页。进程内作业状态在服务重启后失效；用户作品依靠浏览器或导出项目保留。
